# 项目经历：基于 RK3506 的 EtherCAT 伺服控制系统

目标方向：嵌入式 Linux 开发、工业控制及软硬件系统开发。

## 简历正文

**基于 RK3506 的 EtherCAT 伺服控制系统｜实习项目｜独立开发**

**技术栈：** C、嵌入式 Linux、Buildroot、EtherCAT/IgH、CiA402、LVGL、POSIX 多线程、Unix Domain Socket、原理图与 PCB 设计。

**项目简介：** 面向伺服电机控制与状态监测，独立完成控制硬件设计、嵌入式软件开发和上板联调，实现位置控制、运动测试及图形化操作。

- **硬件与系统集成：** 完成基于 RK3506 的控制硬件原理图设计、PCB 布局布线、焊接及上板调试；基于 Rockchip SDK 与 Buildroot 集成 EtherCAT 主站、控制程序和运行依赖，完成软硬件系统联调。
- **总线与运动控制：** 基于 IgH 主站实现 PDO 映射、SDO 参数配置和 DC 分布式时钟同步，按 CiA402 状态机实现伺服使能、故障复位及 CSP 周期同步位置控制；完成电子齿轮与角度/脉冲换算，实现位置设定、相对运动和正反转点动。
- **实时性与运行可靠性：** 采用 SCHED_FIFO、CPU 亲和性、内存锁定及绝对时间周期调度，结合网卡 IRQ 亲和性和线程优先级配置开展实时性优化；实现周期抖动、唤醒延迟及超期计数监测，以及总线就绪检测、启动重试和运动超时处理。
- **交互与部署验证：** 使用 LVGL 开发电机控制与状态监测界面，通过 Unix Domain Socket 连接界面与控制后台，显示实际/目标位置、伺服状态、总线状态及周期抖动；集成开机启动脚本和运动自检流程，完成上板运行验证。

## 面试准备重点

1. 为什么选择 RK3506 和嵌入式 Linux？硬件设计中最难的问题是什么，如何定位和验证？
2. CiA402 状态机如何从不可使能切换到 Operation Enabled？为什么启动时要处理实际位置与目标位置接管？
3. DC 同步解决什么问题？为什么配置 2 kHz 或 4 kHz 不等于证明系统满足该频率下的实时性要求？
4. 周期抖动和唤醒延迟如何计算？统计窗口、多长测试和什么负载能支撑你的性能结论？
5. 为什么拆分 LVGL 界面和控制后台？界面退出或通信超时后，控制系统如何处理？
